# 可核验性转化可行性（抽样 30 句）

> 问题：那 81.5% 不可核验的声明，有多少能被转化成可测形式？

## 结果

| 指标 | 数值 |
|---|---|
| 抽样 | 30 句含"完成/成功/提升/正常"的真实报告句 |
| **模型声称可转化** | **20/30（66.7%）** |
| 人工抽查后**具体可执行** | **约 10–12/30（33–40%）** |
| 其余 | 把抽象名词当对象，不可执行 |

## 两类转化

**真实可用**（对象具体、能被原语检查）：

| 原句 | 转化 |
|---|---|
| "QQ 数据目录依然只有…" | 目录计数、文件存在 |
| "QQ.exe 版本是否变成 9.9.36" | 文件存在、内容包含 |
| "安装程序 315 MB" | 文件存在、文件大小 |
| "curl -I 返回 404，GET 返回 200" | HTTP 状态码 ×2 |
| "网页、桥接 3100、DSH 正常" | HTTP 状态码、端口监听、进程存活 |

**名不副实**（把抽象概念当作可查对象）：

| 原句 | 所谓的转化 | 问题 |
|---|---|---|
| "私聊这条路径断了" | 进程存活(私聊消息处理路径) | **不存在这个进程** |
| "部署工具链都正常" | 进程存活(部署工具链) | 笼统名词 |
| "任务完成耗时约 30 分钟" | 时间(任务完成耗时) | 无可查对象 |

## 结论

**转化率约 1/3（具体可执行），高于 30% 的可行性门槛。**

这支持一个此前没有 benchmark 的方向：

> **可核验性工程**：不是对不可验声明一律弃权，而是把它**转化为可测形式**；
> 评测指标应是 **转化率 × 可执行率**，而不是只看模型声称能转化多少。

## 边界

- n=30，单模型，一次抽样；
- "具体可执行"是人工判读，未做双人标注；
- 转化后的断言**尚未**接回 DSL 执行——执行率未知；
- 部分原句本身有歧义（"链路已经通了"），转化价值有限。
