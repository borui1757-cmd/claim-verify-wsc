# 论文主线：测量 · 干预 · 证据 · 覆盖

> 这不是「又一个核验插件」，而是一条完整的研究叙事：
> **先测出问题有多大，再证明干预有效，再给出可验证的证据，最后说清覆盖面与代价。**
> 四段各有数据、各有边界，合起来才构成贡献。

## 研究问题（一句话）

> 智能体的「完成声明」有多少是假的？能否被**程序客观核验**？核验结论能否**改变模型行为**并被**第三方验证**？

---

## 第一段 · 测量：问题有多大

| 项 | 内容 |
|---|---|
| 问题 | 真实会话里，多少完成声明与实际不符？多少根本无法核验？ |
| 方法 | 从 `~/.dsh/sessions` 重建「报告 + 工具轨迹」案例；提取可核验声明；用程序真值判定 |
| 数据 | 80 会话 → 1,141 案例；27 条真实声明中 **9 条可判、18 条无证据** |
| 结论 | **可核验声明密度极低**：1,140 份报告 / 16,763 句 → 13,147 条声明候选，**仅 18.5%（2,426 条）可核验**；中位数每份报告 **2 条**，**25% 的报告一条都没有** |
| 边界 | 单机、单用户；不含他人会话 |
| 素材 | `bin/harvest.mjs`、`eval/report-trace-bench.mjs`、§7.2、§7.6 第 1 条 |

**这是本文的第一个发现**：agent 报告里的可核验声明**不是少一点，是极少**——这直接决定了「事后核验」这类方案的收益上限。

---

## 第二段 · 干预：核验反馈能否改变模型

| 实验 | 设计 | 结果 | 代价 |
|---|---|---|---|
| **不可恢复失败** | 写入永远落影子目录 | 谎报 **100% → 0%** | token ×2.5 |
| **可恢复失败** | 第一次静默失败、第二次成功 | 任务成功率 **0% → 100%** | token ×3.2、轮次 ×2.5 |
| **形态变化** | 三臂：无回写 / 无上限 / 带上限 | 谎报→存疑→**如实承认** | 上限不省 token，但改善交接质量 |

**结论**：
- 回写能消除「无保留的谎报」；
- 在**可恢复**失败上，还能把任务**做成**；
- 但它**拉长流程、增加成本**，且只在有客观证据时有效。

**边界**：n=8–10、单模型、失败为注入；定位是**存在性证明 + 成本刻画**，不是统计推断（与 [Repair Economics](https://zenodo.org/records/23117824)、[Not All Repair Helps](https://zenodo.org/records/21676556/files/Not%20All%20Repair%20Helps.pdf) 一致）。

**素材**：`eval/ab-task.mjs`、`eval/ab-task-recover.mjs`、§7.6

## 第三段 · 证据：结论能否被第三方验证

| 项 | 内容 |
|---|---|
| 机制 | 判定 → 签名回执（Ed25519 信封）→ 哈希链 → RFC 3161 时间戳 |
| 标准对齐 | 行哈希与链符合 **AIVS（IETF draft-stone-aivs-01）**，可用 `bin/aivs-verify.mjs` 独立校验 |
| 实测 | 10 份回执逐条验签通过；链完整；锚点一致；改一条即失败 |
| 关键定位 | AIVS 第 9.2 节明确「不证明内容为真」——**本文补的正是这一格** |

**素材**：`lib/aivs.js`、`lib/envelope.js`、`test/aivs.mjs`、§3.7、§6.7

---

## 第四段 · 覆盖：把「能判的」做大

| 手段 | 效果 | 状态 |
|---|---|---|
| 声明**原子分解** | 实测 **+0**（抽取器本就全文扫描） | 已否决（有数据） |
| **新增 oracle**（git / HTTP） | 直接覆盖「已提交/工作区干净/接口 200」 | ✅ 已实现（12 原语） |
| **结构化声明**（`report_claims`） | 把声明密度从「偶然」变「每轮必报」 | ✅ 已实现 |
| 更宽证据窗口、DB/CI 原语 | 待做 | ⏳ |

**诚实结论**：覆盖率提升主要靠**加 oracle 源 + 让 agent 结构化声明**，不靠拆句子。

**素材**：`lib/vcs-http.js`、`lib/report-tool.js`、§3.2、§3.8

## 四段之间的关系（为什么必须组合）

```
测量（问题多大）—— 决定值不值得做干预
    ↓
干预（改了没有）—— 决定这条路是否有效
    ↓
证据（能否被验）—— 决定别人能不能信
    ↓
覆盖（能做多大）—— 决定适用面
```

**任一单独拿出来都弱**：
- 只测量 → 观察性研究，没有方案
- 只干预 → n 小、像 demo
- 只证据 → 工程组件
- 只覆盖 → 加原语，无科学问题

**合起来**：有发现、有干预、有验证、有边界。

## 与既有工作的关系（空位在哪）

| 既有 | 做了什么 | 没做什么 |
|---|---|---|
| SOF / CapScope / VeriGuard | 执行前授权 | 不核验「做成了没有」 |
| GUI report–trace auditing | 报告隔离 + 规则审计（F1 0.75–0.81） | 界面域；无分发凭证 |
| AIVS（IETF） | 日志完整性、身份、离线验证 | 明说不证内容为真 |
| Repair Economics / Not All Repair Helps | 修复收益与成本 | 不做可验证证据 |
| Intent-Execution Correspondence | 意图-执行一致性度量 | 无 OS 真值 + 回执闭环 |

**空位**：以 **OS 状态为唯一裁判**、**判定零模型调用**、**结论可分发验证**、并**把结论回写给模型**的组合。

---

## 四条贡献（可直接放绪论）

1. **测量**：量化 agent 完成声明的可核验密度（33%）与写作习惯（稀疏、无对象）。
2. **干预**：首次在同一系统中给出「回写→重试→任务做成」的实测（0%→100%），并量化其代价（×3.2 token）。
3. **证据**：与 AIVS 对齐的可分发回执，第三方可离线验证；补齐标准声明不覆盖的「内容真实性」。
4. **边界**：明确弃权语义与覆盖率-风险取舍，给出可复现的评测与反循环论证（控制/蜕变/变异/差分）。

### 修正后的定位（唯一还站得住的）

> 不是「没人做过」，而是：**在操作系统可查事实这一子域上，把「确定性判定（零模型）→ 可分发回执 → 回写给模型形成闭环」串起来的实现，尚未见到有影响力的工作。**

四段各自的处境：

| 段 | 处境 |
|---|---|
| ① 测量 | **已有人做**（OverclaimBench，更强）→ 只做本地复现与引用 |
| ② 干预 | 有相邻工作（Repair Economics / RECEIPT）→ 我们补「OS 真值触发 + 真实宿主闭环」 |
| ③ 证据 | 有标准（AAR / AIVS / SCITT）→ 我们做对齐与组合 |
| ④ 覆盖 | 真正较少人做：OS 原语 + 结构化声明 + 弃权语义 |

**结论**：论文应写成「**组合与落地**」而非「提出新问题」。这一点必须在绪论里先说清，否则会被当作重复劳动。
