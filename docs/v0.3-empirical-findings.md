# 实测结论（2026-11-05，本机 12 个会话 / 284 个有工具的轮次）

三个方案都拿真实数据跑过。**结论与最初的设想有出入，按实测修正。**

## 方案 A：严格句式对账（动作词 + 反引号路径）

正则：`(?:已|已经)?(?:写入|创建|新建|保存|修改|更新)(?:了)?\s*`路径``

| 指标 | 结果 |
|---|---|
| 能抽到的断言 | **13 条 / 804 条动作类断言 = 1.6%** |
| 覆盖轮次 | 10 / 284 |

**结论：不可行。** 真实报告几乎不写「写入 `C:\x`」这种格式，绝大多数是「重启了」「做好了」
「全部完成」。而且抽到的 13 条里有一半是相对路径（`~/.dsh`、`auths/`、`relay/server.mjs`），
还得再做相对路径解析才能对账。

## 方案 B：宽松句式对账（动作词 + 句内就近路径）

| 判定 | 条数 | 占比 |
|---|---|---|
| pass | 335 | 41.7% |
| flag | 177 | 22.0% |
| review | 290 | 36.1% |

看起来「63.8% 可自动判定」很漂亮，**但样本一看就知道是假的**：8 条 flag 全挤在同一轮，
原因是那一轮有 3 条无关命令失败，就把「重启」「做好了」判成了 flag。

把规则收紧成「必须绑定对象才判定」后：**可判定比例掉到 0.7%**（2 pass + 4 flag）。

**结论：轮次级证据太粗。** 「本轮有一条命令失败」不等于「这条断言失败了」，
必须做到断言 ↔ 具体动作的绑定，而这在没有对象的情况下做不到。

## 方案 C：失败未汇报检测（不用对账断言）

规则：本轮存在 `isError` 的工具结果，但报告里没有任何失败类措辞 → candidate。

| 指标 | 结果 |
|---|---|
| 有报告的轮次 | 313 |
| 出现过工具失败的轮次 | 110 |
| **失败但报告没提** | **26（占出错轮次 23.6%，占全部轮次 8.3%）** |

**这是三条里唯一可行的方向**，但当前误报率明显偏高，抽查出的原因有三：

1. **AbortError 不算失败**——用户中断（`turn 9`）被当成工具失败
2. **措辞表不全**——`turn 15` 的报告写了「robocopy 的退出码 9 是它不认参数」，
   这是**明确承认失败**，但我的词表里没有「退出码/不认参数」这类说法，被漏判成 silent
3. **粒度过粗**——`turn 10/11/14` 里部分调用失败、报告讲的是其他成功项，需要按动作对齐

## 对 v0.3 的修正

原设计（对账报告里的动作断言）**覆盖率撑不起来**，改成：

```
主路径：失败未汇报检测
  ├─ 过滤 AbortError / 用户中断
  ├─ 失败措辞表扩充（退出码 N、不认参数、没生效、被拒、拒绝、超时…）
  └─ 按「失败的工具 → 它操作的对象（路径/命令）」与报告提到该对象的段落对齐

辅助路径：带对象的高置信断言（写入 `绝对路径`）继续对账，覆盖少但精度高
```

**定位也要跟着改**：不是「核验 agent 说的每个动作」，而是
**「盯住它做了但搞砸了、却没说出来的那部分」**。这个目标更小，但可检测性强得多。
