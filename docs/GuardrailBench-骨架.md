# GuardrailBench：确定性护栏的五条判据

> **动机**：2026 年的多篇工作都在呼吁「自我改进的 agent 需要确定性护栏」（如 [LLM-as-a-Judge is not an Oracle](https://export.arxiv.org/pdf/2609.02246)、[VIGIL](https://arxiv.org/html/2606.26524v1)、[Deterministic Runtime Enforcement](https://ieeexplore.ieee.org/document/11641546)），
> 但**没有人定义「怎么证明一个护栏是确定性的」**。
> 本文提出五条可测判据，并给出最小评测协议。

状态：**提议稿**（内部）。尚无外部采用，先自我检验。

**已有自评工具**：`eval/guardrail-check.mjs`

```bash
node eval/guardrail-check.mjs \
  --cases data/harvested-cases.jsonl \
  --density eval/claim-density.md \
  --cost eval/ab-task-recover.md
```

输出五条判据的逐项结果与通过数（我们当前 **4/5**，缺在覆盖面 18.5% < 30%）。

---

## 一、为什么需要这个

现状是三种混用：

| 说法 | 实际含义 | 问题 |
|---|---|---|
| “我们的护栏是确定性的” | 判定用规则不用模型 | 规则也可能依赖环境、时钟、随机 |
| “误报很低” | 在自建集上低 | 换数据集就变 |
| “可复现” | 我们能跑出同样结果 | 第三方不一定能 |

**五条判据把这三句话变成可测的。**

---

## 二、五条判据

### 判据 1：确定性（Determinism）

**定义**：同一输入（证据快照 + 声明）重复执行 N 次，输出**逐字节相同**。

**怎么测**：
```
固定证据快照 → 跑 N=20 次 → 比较 (verdict, reason) 的哈希
```

**我们的现状**：✅ 已覆盖。判定期零模型调用；属性测试 P1–P5 共 640 次随机执行无不一致。

**缺口**：**没有对「时间相关原语」做确定性验证**（`time_near`、`port` 会随环境变化）。需要区分「确定性判定」与「时效性证据」。

---

### 判据 2：可复验（Replayability）

**定义**：第三方仅凭产物（回执 + 证据快照），**不接触原系统、不运行原 agent**，能重算出同一判定。

**怎么测**：
```
把 (report, evidence snapshot, receipt) 交给第三方
第三方执行 replay 脚本 → 判定必须与原判定一致
```

**我们的现状**：✅ 基本覆盖。`cases.jsonl` 存证据快照，`bin/replay-batch.mjs` 可重放；回执带 digest。

**缺口**：**没有「只有回执、没有快照」时的复验路径**——目前回执证明“某人给出过这个判定”，不包含足够信息重算。

---

### 判据 3：覆盖面（Coverage）

**定义**：在目标语料上，护栏能给出**非弃权结论**的比例。

**怎么测**：
```
覆盖率 = (supported + contradicted) / 全部声明
```

**我们的现状**：✅ 已测。- 18.5% 可核验（1,140 份报告 / 16,763 句）
- 真实会话回执：27 条声明中 9 条有结论（33%）

**缺口**：覆盖面**强依赖原语集合**，换域就变；需要报告「原语清单 + 该清单下的覆盖率」。

---

### 判据 4：误报代价（False-Positive Cost）

**定义**：护栏误判（把对的判成错）一次，下游要付多少代价。

**怎么测**（三种口径，按可用性选）：
```
① 人工复核成本：误报一条要几分钟
② 中断成本：误报导致 agent 重试的额外 token / 轮次
③ 机会成本：误报导致任务被判失败的概率
```

**我们的现状**：⚠️ 部分覆盖。
- 中断成本已测：回写触发后 token ×2.5–3.6、轮次 ×2–2.5
- 误报率本身在构造集为 0，但**真实分布的误报率未知**

**缺口**：这是五条里最弱的一条，需要真实使用数据。

---

### 判据 5：弃权边界（Abstention Boundary）

**定义**：护栏在什么条件下**必须**弃权，而不是给结论。

**怎么测**：
```
构造"不可判定"集合 → 要求全部返回 insufficient
构造"模糊但可界定"集合 → 记录行为（判 or 弃权），并要求文档化
```

**我们的现状**：✅ 部分覆盖。
- 主观句 10/10 判 `insufficient`（dsl-bench）
- 无证据 → `insufficient`（不判否定）

**缺口**：**模糊声明的处理未定义**——"2:40 多"这类句子，当前靠容差放行，属于设计漏洞（见 `FUTURE-IDEAS.md`）。

## 三、最小评测协议

任何护栏按以下步骤自评，产出可比结果：

| 步骤 | 内容 | 产出 |
|---|---|---|
| S1 | 声明 5 条判据的**自评结果** | 表格 |
| S2 | 固定一份证据快照集（≥100 条） | 数据文件 |
| S3 | 跑 N=20 次确定性测试 | 哈希一致性 |
| S4 | 交给第三方重放 | 一致率 |
| S5 | 报告覆盖率 + 原语清单 | 数字 |

**通过条件（建议）**：

```
判据1：20/20 输出一致
判据2：第三方重放一致率 ≥95%
判据3：覆盖率 ≥30%（并声明原语清单）
判据4：误报中断成本已量化
判据5：不可判定集合 100% 弃权
```

## 四、与现有工作的关系

| 工作 | 提供什么 | 缺什么 |
|---|---|---|
| [Deterministic Runtime Enforcement](https://ieeexplore.ieee.org/document/11641546) | 执行层强制 | 无评测口径 |
| [VIGIL](https://arxiv.org/html/2606.26524v1) | 运行时规范强制 | 评测在自定义任务上 |
| [LLM-as-a-Judge is not an Oracle](https://export.arxiv.org/pdf/2609.02246) | 论证需要护栏 | 未给指标 |
| [OverclaimBench](https://arxiv.org/abs/2609.20812) | 声明准确率指标 | 不做护栏评测 |
| **本文（提议）** | **五条可测判据 + 最小协议** | 需外部采用才成立 |

## 五、落地路径

1. **自评**（现在就能做）：写一个 `eval/guardrail-check.mjs`，对本项目打五条判据的分。
2. **开源**（投稿前）：把 `eval/` 脱敏后发布，让别人自评。
3. **论文**（作为工具论文的一节，或单独短文）：重点不是"我们做了护栏"，而是"**怎么证明护栏是护栏**"。

## 六、风险

| 风险 | 说明 |
|---|---|
| 判据武断 | 五条是提议，不是标准；需要外部讨论 |
| 自评即自证 | 必须由第三方复验（判据 2 就是为此设计） |
| 覆盖面依赖域 | 需同时报原语清单，否则数字无意义 |
