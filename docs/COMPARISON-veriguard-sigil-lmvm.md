# 对照笔记：VeriGuard / SIGIL / LMVM —— 我们在“意图→执行”链上的位置

日期：2026-11-05
目的：给「自然语言 → 机器执行」这条链找位置，分清谁做了什么、我们缺什么、能接什么。

---

## 1. VeriGuard（arXiv 2510.05156，2025-10）

**一句话**：给 LLM agent 的**动作**做形式化安全保证，双阶段。

**机制**
- 离线：澄清用户意图 → 生成行为策略（behavioral policy）→ 测试 + **形式化验证**，迭代到证明通过
- 在线：作为 **runtime monitor**，在每个动作执行**前**，用已验证的策略检查该动作

**关键点**：验证发生在**执行前**，对象是“**将要做的动作**”。
**实验**：22 页；医疗等敏感域为动机。

**与我们**
- 重叠：都关心“agent 行为是否合规”
- 差异：VeriGuard 管**动作前**；我们管**结果后**（回执、真值核对）
- 可借鉴：它们的 `clarify intent → policy` 流程，正好对应我们的“先把断言形式化”那一步

---

## 2. SIGIL（Zenodo 22499275，2026-09，v2）

**一句话**：为 **agent 自己写的代码**设计的能力安全语言 + 验证管线，把安全约束放到**构造级**。

**机制**
- 线性 capability 类型、显式 effect rows、信息流污点、双环 WebAssembly 隔离
- 构造期就做 **SMT 检查**（可判定片段：无量化位向量 + 线性整数算术）
- Lean 4 机械化证明（160 定理、0 sorry）证明类型/能力/隔离/污点性质
- 运行期仍隔离（Wasmtime store、fuel、显式授权）

**实验**：67 个对抗安全用例、10 个 CVE 改造、214 个工具/程序、Z3 验证 5–8ms 中位。

**与我们**
- 重叠：都认为“事后过滤不够”，要在执行前卡住
- 差异：SIGIL 卡的是**代码**，粒度细、代价是要求 agent 用一门新语言；我们卡的是**声明**，粒度粗、代价是要求 agent 交付带证据
- 可借鉴：它的 `effect rows` 思路可以拿来设计我们的可写原语（每个原语声明副作用）

---

## 3. LMVM（Zenodo 20517334，2026-06）

**一句话**：英文指令 → LLVM IR → clang 编译 → 原生二进制，直接跑在 CPU 上。

**机制**：LLM 当 IR 生成后端；检测平台/CPU/工具链；IR 经 clang/llc/lld 编译成可执行文件；可跑裸机 / Docker / Lambda。

**卖点**：native 比解释执行快 10–50x（作者自述，未独立复现）。

**与我们**
- 它是“**翻译层**”的极端形态：跳过高级语言，直接到 IR
- **完全没有验证环节**——LLM 写的 IR 直接编译执行，这是它最大的风险
- 正好反证我们的判断：**翻译越激进，越需要执行前后的核验**

---

## 4. 三者拼起来的缺口

| 阶段 | 谁在做 | 代表 |
|---|---|---|
| 翻译（NL → IR/代码/编排） | 已有多家 | LMVM、CUDABench、意图编排 |
| **执行前**约束（策略/类型/污点/SMT） | 有，且很硬 | VeriGuard、SIGIL |
| **执行后**核验（它说的和实际做的是否一致） | **几乎没有系统工作** | 我们 |

**我们的定位一句**：
> 在意图编译链上，前两段都有人把守；第三段（执行后“它到底做没做”）目前只有零散工具，我们把这一段做成可验证的证据。

---

## 5. 可立刻借鉴的三件事

1. **把 DSL 原语做成“带声明副作用”的**（SIGIL 的 effect rows）：
   `exists` = 纯读；`delete_dir` = 写、需授权、需回执。
2. **接 VeriGuard 的思路做“执行前策略”**：可写原语的每次调用先过策略，再执行。
3. **回执里带上策略版本**：证明“这次执行是在哪版策略下发生的”（审计需要）。

## 6. 论文可用的表述（草稿）

现有工作要么保证“**将要做的动作**合规”（VeriGuard），要么保证“**生成的代码**安全”（SIGIL），
但 agent 报告里最常见的问题不是动作不合规，而是**动作根本没发生却声称发生了**。
本文把这类“执行后断言”形式化为可判定的检查问题，并给出可第三方验证的证据回执。
