# 对接说明：把判定层换成确定性实现

> 适用场景：你的 agent 核验流水线已经有「声明捕获 + 证据收集 + 干预策略 + 日志」，
> 但判定那一步依赖**外部分类器/LLM**（要 API key、有采样噪声、不可离线复现）。
> 本模块提供纯函数接口，可替换那一段。

## 接口

```js
import { adjudicate, shouldIntervene } from 'claim-verify-wsc/lib/adapter.js';

const { verdict, detail } = adjudicate(facts, claim);
// verdict: 'supported' | 'contradicted' | 'insufficient'
```

**输入**：

```js
facts = {
  writes: [{ path, isError, textFailed, tool, text }],
  cmds:   [{ cmd, isError, textFailed, text, tool }],
  tests:  { run: boolean, passed: boolean | null },   // null = 退出码无法归属
}
claim = { kind: 'write' | 'cmd' | 'test', target }
```

**约束**：
- 纯函数，无网络、无磁盘、无模型调用；同输入必同输出；
- `facts` 缺字段不崩，缺证据一律返回 `insufficient`（弃权，不猜）。

## 三步接入

```js
// 1. 收集证据（你已有）
const facts = collectFacts(session);

// 2. 换掉原来的分类器调用
// 之前：const p = await jev.classify(state);
// 之后：
const { verdict } = adjudicate(facts, { kind: 'test', target: 'npm test' });

// 3. 干预策略保持不变
if (shouldIntervene(verdict)) {      // 只有 contradicted 才打断
  steer('上一轮声明与记录不符');
}
```

## 语义对照

| 你的分类器输出 | 本模块 |
|---|---|
| `requirements_satisfied` 高 | 不适用——本模块不判"需求是否满足" |
| `evidence_matches_claim` 高 | `supported` |
| 证据反驳声明 | `contradicted` |
| 证据不足 | `insufficient`（**默认放行**） |

**注意**：本模块**不判断"任务是否完成"**，只判断"这条具体声明是否被记录支持"。
「需求是否满足」属于语义判断，仍需人或 LLM。

## 能替换掉的与必须保留的

| 环节 | 能否替换 |
|---|---|
| 证据收集 | 保留（你的 facts 更贴近你的系统） |
| 判定"声明 vs 记录" | ✅ **可替换**（确定性） |
| 判定"需求是否满足" | ❌ 不能（语义问题） |
| 阈值与预算 | 保留（本模块没有阈值，只有三分类） |

## 已验证的行为（`test/adapter.mjs`，15/15）

| 场景 | 输出 |
|---|---|
| 有成功写入记录 | supported |
| 只有失败写入 | contradicted |
| 没有该文件的记录 | insufficient |
| 声称测试通过但没跑 | contradicted |
| 测试跑了但失败 | contradicted |
| 测试跑了、退出码不可归属 | insufficient |
| 命令被 `;` 包装掩盖退出码 | insufficient |
| 空 facts | insufficient |

## 已知边界

- 只覆盖**有客观记录**的声明（写入、命令、测试）；主观与知识类不在内；
- 退出码归属依赖命令文本分析（`exit-attr.js`），只处理 `;`/换行分隔的常见形态；
- 不做跨工具链条追溯（见论文 §7.6.23），需要上游自己传 provenance。
