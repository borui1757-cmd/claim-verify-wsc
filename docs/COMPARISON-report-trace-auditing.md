# 对照：Report–Trace Auditing（arXiv 2610.29609）与本项目

日期：2026-11-05　来源：https://arxiv.org/abs/2610.29609（Research Track 已录用，2026-10-21）

## 一、他们做了什么

**问题定义**
- 运行 u = (x, τ, m)：任务 x、轨迹 τ、最终报告 m
- **dangerous misreport**：agent 声称成功，但轨迹不显示"它自己造成了目标结果"
  （仅最终界面符合不够：目标状态可能原本就存在、列表本来为空、改了没保存）

**关键发现：self-report leakage（自我报告泄漏）**
- 同一个 judge、同一份任务与轨迹，只决定"是否给它看 agent 的自述"
- 不给自述时，轨迹核验的 dangerous-misreport 召回率提高：
  - Qwen3.5-35B-A3B：**+43.4 个百分点**
  - DeepSeek-284B-A13B：**+13.3 个百分点**
- 结论：**报告必须隔离**——自述只记录声明，不能影响对轨迹的判断

**系统：report-isolated evidence–policy auditor**
- 拆成三段：读报告定"声明意图" / **不看报告**抽取轨迹证据 / 确定性规则给出 pass·flag·review
- 证据与策略分离 → 同一份审计记录可换策略**重放**，无需重新调模型

**数据与结果**
- 1,384 次 GUI-agent 执行中筛出 **465 条审计记录**，含 **180 条 dangerous misreport**
- F1 **0.75–0.78**；留出集 Batch 2 **0.77–0.81**
- 门禁模式下拦截 **74–90%** 危险误报，检查负载 **45–56%**；粗筛后仅占全流 **16–19%**

## 二、与本项目的关系

| 维度 | 他们 | 我们 |
|---|---|---|
| 场景 | GUI agent（手机/界面操作） | 编码/运维 agent（OS 状态） |
| 证据 | 轨迹里的界面状态 | **本机真值**：端口/路径/进程/时间/算式 |
| 判定 | 确定性规则 + 抽取证据 | DSL 编译成只读检查 + 程序执行 |
| 隔离 | 报告隔离（本文的核心贡献） | 我们把"声明"与"证据"分开，但**没做泄漏实验** |
| 证据产物 | 可重放的审计记录 | **Ed25519 信封 + 哈希链 + RFC3161 时间戳** |
| 数据 | 465 条审计记录（自有语料） | 37 条自产标签 + 60 条构造评测 |

## 三、直接可借鉴的四点

1. **报告隔离是硬要求**：我们现在把报告和证据一起喂给模型判（sentenceAudit），
   按他们的发现，这会**压低召回**。应当：抽取证据时不看报告，只让"声明解析"看报告。
2. **指标改用他们的口径**：dangerous-misreport recall @ inspection load，
   比我们的 F1 更贴近"能不能拦住"。
3. **可重放是卖点**：我们的 `cases.jsonl` + `replay-batch` 已经是这个形状，可以明说。
4. **三档处置**：pass / flag / review，比我们的 supported/contradicted/insufficient
   更贴审批流程（flag 与 review 都阻断自动通过）。

## 四、我们的差异化（论文里必须咬住）

1. **OS 级真值**：他们只能看 GUI 状态；我们能探端口、读文件、查进程、算时间
2. **密码学证据**：回执可被第三方用公钥独立验证（他们输出的是审计记录，不是可分发凭证）
3. **零成本判定**：结构层与 DSL 执行不依赖模型判断

## 五、风险

- 题目撞车：`report–trace auditing` 已被占，且已有 465 条数据与 F1 数字
- 我们的数据量（37 条）与他们（465 条）差一个数量级
- 若我们的实验设计与他们高度重合，会被视为"复现 + 小改动"

## 六、结论

他们证明了"问题真实 + 报告隔离必要 + 规则审计可行"。
我们若要发，必须换一个**他们没做的维度**：**真值来源（OS 而非界面）+ 可分发凭证（密码学回执）**，
并且最好能在他们的指标口径上报一个可比数字。
