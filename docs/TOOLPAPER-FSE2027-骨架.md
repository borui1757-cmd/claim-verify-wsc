## 一、标题与定位

**候选标题**

1. *PhantomCheck: Verifying What Agents Claim They Did*
2. *Verifying Agent Completion Claims Against Operating-System State*
3. *Receipts for Claims: Closing the Gap Between Agent Reports and Reality*

**一句话定位**

> 现有可观测性记录「代理做了什么」，但不回答「**它说做成了，是否为真**」。
> 本工具以操作系统状态为唯一裁判，把完成声明判成 支持/反驳/无证据，并以可验证回执分发；结论可回写给模型。

**四条贡献（第 4 条是这一轮新增的）**

> **贡献的性质：不是"发明新药"，是"配出方子"——并测了剂量、时辰、与拮抗。**
> 单项机制都有先例；缺的是"哪味药、多大剂量、什么顺序、哪两味相冲"。

1. 确定性裁决器（14 类只读原语，判定期零模型调用）
2. 弃权作为一等结果（真实语料 18.5% 可核验，弃权是常态）
3. 可验证回执 + 可复跑命令的回写
4. **联合干预方案（regimen）+ 剂量/时序/拮抗的实测**：

| 成分 | 剂量 | 效果 |
|---|---|---|
| 事前接种（描述失败模式） | 无 → 描述性 | 判失败 **0/20 → 13/20** |
| 措辞指令 | 追加 | **13/20 → 20/20**（改表述，不改判断） |
| 判定带 `mismatch` | vs 只有 `ok` | 无保留谎报 **20/20 → 0/20** |
| 只带 `size` | vs 只有 `ok` | **拮抗**：20/20 → **19/20** |
| 事后提醒 | — | **无效** |

**并且明确**：机制层不新（hermes-agent 的 verified 字段、pi-warden 的 intent-mismatch、
Inoculation Prompting、AI Contract Programming 都已有），**新的是这份"药学式"测定**。

**与 FSE 评审口味的对齐**：工具轨看重「工具可用、演示清晰、实现可信」，**不要求大规模实证**——我们已有小规模实证，属于加分项。

## 三、三个演示场景（演示轨的核心，必须一次看明白）

**场景 A：静默失败被抓住**
```
1. 代理执行「写入 out-0.txt」，工具返回 ok
2. 核验器检查真实路径 → 文件不存在
3. 屏幕出现【核验】提示
4. 代理重试，第二次真正落盘
```
看点：**同一句「已写入」，工具说成功、系统说没有**。

**场景 B：回执可被第三方验**
```
1. 现场生成回执
2. 拔出网络，运行 bin/aivs-verify.mjs
3. 输出：链完整、验签通过
4. 手动改一行 → 立刻报错
```
看点：**离线、无信任第三方**。

**场景 C：弃权而不是乱判**
```
1. 报告里一句「系统已优化，性能提升明显」
2. 核验器输出 insufficient（没有客观真值）
3. 说明为什么弃权，而不是给个假结论
```
看点：**敢于说「不知道」**。

**场景 D：失败的写入从不落地**
```
1. 故意写入一个"是目录"的路径 → rename 失败
2. 目标没有被破坏，临时文件已清理
3. 正常覆盖 → 生成备份 → restore_file 撤销 → 内容回到 v1
```
看点：**原子提交 + 可撤销**，比"事后回滚"更强。

## 八、四页正文骨架（可直接扩写）

**1 Introduction（0.75 页）**
- 首段：编码代理越来越自主，用户只能读它的最终报告。
- 二段（引用数据）：OverclaimBench 报告 67.9% 的运行未读完文件，其中 80.4% 的表述具误导性。
- 三段：现有工具记录“做了什么”（OTel、LangSmith、AIVS），不判断“说做成了是否为真”。
- 四段：本文工具做三件事——核验、弃权、发凭证。
- 贡献三条（要点式）。

**2 Motivation（0.5 页）**
- 我们的测量：18.5% 可核验、中位 2 条、25% 为零。
- 事故：Replit 2025（删库后伪造记录）。
- 缺口表：可观测性 / 授权 / 凭证 各回答什么，缺哪一格。

**3 Design（1.0 页）**
- 3.1 真值来源：14 个只读原语（Tab.1），分 `os`（现状）与 `trace`（历史）两类。
- 3.2 判定：DSL 程序 → supported/contradicted/insufficient；零模型调用。
- 3.3 回执：Ed25519 信封 + 哈希链 + RFC 3161；行哈希对齐 AIVS。
- 3.4 回写：结论注入下一步消息；同目标限 2 次后升级。
- 3.5 **原子性与撤销**：写入走 `tmp → 校验 SHA-256 → 原子 rename`，失败的写入**从不落地**；覆盖前自动备份，`restore_file` 一键还原。边界：任意 shell 副作用只核验、不回滚。
- 3.6 **外部世界模型（账本）**：每条核验结论追加到 `worldmodel.jsonl`（带时间戳与判定，按类型设 TTL）；
  它对模型提供三件事——**记忆**（"10 分钟前成立、现在不成立"）、**自校准**（7 天反驳率 ≥50% 时提醒谨慎）、
  **免疫**（同一对象被证伪 ≥2 次后升级措辞）。三者均只读账本、**零模型调用**。
  这回应了"核验器不更新模型世界模型"的质疑：我们不训练，但把世界模型**外置**为可追溯的账本。

**4 Implementation（0.5 页）**
- 插件形态（宿主钩子）、零运行时依赖、**43 个断言式测试**、跨平台（Windows 已验，POSIX 走规范符合性）。

**5 Demonstration（1.0 页）**
- **四个场景**（A 静默失败 / B 回执 / C 弃权 / D 原子写），每个配一张小图或代码框。

**6 Preliminary Evaluation（0.5 页）**
- Tab.2 八行数字；配 Fig.4（回滚 vs 反馈）。
- 一句成本说明（token ×3.2–3.6）。
- 一句边界：注入式失败、单模型、n=6–8。

**7 Related Work & Availability（0.25 页）**
- **开头先立靶**：模型判官不是 oracle（arXiv 2609.02246），无外部反馈的自我纠正不成立（Huang 等）——本文提供确定性裁决位。
- **同层实现（必须先承认）**：把核验结论放进工具结果并非首创——`hermes-agent` 的 `write_file` 已返回 `verified` 字段；
  契约式后置条件在 agent 系统里也有专文（AI Contract Programming, 2026）。本文**不主张该机制新**。
- **本文独有的是对照数据**：工具形态 4/4 如实 vs 事后消息 0/4；`ok` 1/6 → `ok+size` **3/6** → `ok+size+mismatch` **0/6**；
  以及"语气强弱无差异"的阴性结果。
- 五条差异（SOF / GUI 审计 / AIVS / Repair Economics / OverclaimBench）。
- 仓库链接、安装一条命令、Docker 可选。
