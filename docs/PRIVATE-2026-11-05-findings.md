## 二、被证伪的假设（比成果更重要）

**① 「严格句式对账」不可行**
正则抽 `写入 \`路径\`` 只覆盖 **13/804 = 1.6%**。真实报告全是「重启了」「搞定了」这种无对象句式。

**② 「轮次级证据」太粗**
宽松对账看着有 63.8% 可判定，但样本一看就是假的：一轮里 3 条无关命令失败，就把「重启」判成 flag。收紧成「必须绑定对象」后跌到 **0.7%**。

**③ 「外层成功掩盖内层失败」抓不到**
`npm test` 内层失败、外层命令 exit=0 → `isError=false`，且 **stderr 没进 `tool/result` 的 content**。
结论：这个场景**事后读日志无法发现**，除非工具层保留 stderr 或 agent 遵守「一命令一动作」。**认输**。

## 三、当前架构（真实状态）

```
本轮有失败（isError 或输出含失败特征）
   ↓
结构对账（0ms / 0 token）
   ├─ 命中 → 写 audit.jsonl (mode:"structural")
   ↓ 未命中
句子级三分类（~5s，模型）
   → 写 audit.jsonl (mode:"llm")
```

隔离约束：`evidence.js` 签名里没有报告文本；`sentence-audit.js` 只吃证据文档；内部调用带 `__claimVerifyInternal` 防递归。

## 四、未验证 / 风险

1. **`contradicted` 的准确率没测**：只出现过 2 次，都是自己造的样本
2. **结构对账从未在真实轮次触发**：`looksFailed` 依赖 stderr，而 stderr 常被丢
3. **5 秒延迟**：即使有闸门，触发时仍是明显卡顿
4. **`insufficient` 语义模糊**：分不清「证据不足」和「模型没判」
5. **窗口=2 轮**：跨轮更早的动作仍会漏

## 六、对外口径（如果将来要讲）

> 幻觉不可能消除——对任意事实存在数学下限，而主流评测还在奖励猜测。
> 我们只做一件事：agent 说「我做到了」时，用本机真值核对它到底做没做；核不了的，明确说核不了。

**不要说**「独一份」「消除幻觉」「首创」。同类：evidence-judge、agent-claimcheck、trajectory-judge、rashomon、writeguard；学术：ICSE'27 的 report–trace auditing、MiniCheck、ANTE。

## 七、结构对账 v1→v3：三轮被数据打回来的演进

这条路的教训比成果值钱，**每一步都是先以为成了、再被抽样打脸**。

### v1：动词匹配（38.7% 覆盖，全部误报）

用「写入/测试/启动」等动词直接匹配句子，命中就算声明。

- `X = 38.7%`，`contradicted` **570 条**（占 37%）
- **抽查 12 条，12 条全错**

三个根因：
1. **「提到」≠「声称」**——"沙箱拒绝向 .dsh 写入" 被当成"我写入了"
2. **否定句没处理**——"不需要重启" 被判成"声称重启了"
3. **句子切分太粗**——表格行 `| restore | 28.1 MB |` 成了候选

### v2：加 claim detection + NegEx + 对象要求（3.4% 覆盖）

按 ClaimBuster 两段式补了「这句是不是断言」这一层，引号遮蔽、否定窗口、第三方主语过滤、有对象才判。

- `contradicted` **44 条**，抽查约 6/10 像真的
- 但**分母错了**：3963 条是"含动作词"的句子，不是断言

### v3：证据必须可归因（39.4% 对真断言）

发现 v2 还在用"本轮有任何命令失败"当证据——**"3/22 条命令失败"证明不了"服务没重启"**。

改成三档：
- 候选**全部失败** → contradicted（可归因）
- **部分失败** → uncertain（无法归因）
- 全部成功 → supported

- `contradicted` 570 → 44 → **14**，抽查 **5/6 正确**
- 真断言候选 **94 条**，决定性覆盖 **39.4%**
- 那个故意写错的测试（说成功、实际 exit=7）**结构层自己抓到了**，不需要模型

### 量化脚本（可复用）

`eval/coverage-x.mjs`：改完策略跑一遍，直接给 X / contradicted / 抽样。
**这是今天唯一可复用的评估工具，别删。**

### 仍然没测的（不能吹的地方）

1. 结构层 precision **没人工标注**（估 0.85）
2. 模型层 F1 **是借论文的 0.78**，自己没测
3. 分母 94 条本身是规则判的，可能漏

**结论：能不能超过公开的 0.78，取决于这两个未测的数。在那之前所有数字都是自说自话。**

## 八、四个底层假设（v0.4）：我们原先全踩空了

v1→v3 修的是「怎么抽、怎么判」，但底层还压着四个**默认成立却错误**的假设。这一轮逐个处理。

### ① 闭世界假设 → 已修

原来：`本轮没看到写入调用 → 判定"已写入"是假的`。
问题：记录会被裁剪、`tool/result` 会被压缩替换、窗口会滚走。**"没看见"≠"没发生"**。

`trace.pairs()` 一直返回 `truncated` 标志，但 `promise.js` 从来没接。现在：
**`truncated === true` → 所有 contradicted 降级 uncertain**，evidence 注明"证据被截断，无法据此否定"，confidence 0.2。

### ② 因果归因需要反事实 → 做不了，只做顺序校验

[Attributing Agent Failures ... Needs an Executed Counterfactual](https://arxiv.org/abs/2611.05650)：要归因到历史某步，**必须执行一次反事实**（回滚重放）。前沿是 [RECAST](https://neurips.cc/virtual/2026/loc/atlanta/165736)——从静态轨迹做动态重放，在模拟环境里跑。

**我们没有回滚/模拟环境，所以只能做中间态：**
证据必须发生在声明之前（`hit.turn <= claimTurn`）。防的是"拿后发生的事证明前面的话"（提前邀功）。

**对外必须承认：结构层只做一致性检查，不做因果归因。**

### ③ 只建模动作，没建模状态 → 已修（这是最硬的一条）

[GroundEval](https://browse-export.arxiv.org/abs/2606.22737)：有状态 agent 的评估必须以**状态**为准，不以叙述为准。[opendot](https://pypi.org/project/opendot/0.0.2/) 的做法是每个动作前快照。

新增 `lib/state.js`（`statPath` / `hashPath`），写文件类断言**先看文件**：

| 情形 | 判定 |
|---|---|
| 声称写入 X，而 X 不存在 | **contradicted**（日志说什么都没用） |
| X 存在 + 有成功写入调用 | supported（注明"文件已存在"） |
| X 存在但找不到对应写入 | uncertain（可能是旧文件） |

**这是插件第一次拥有「不依赖日志」的真值来源。** 它同时治好了三个已知盲区：stderr 丢失、轨迹裁剪、调用成功但没生效。

局限：没有 turn 开始时的基线快照，所以还判断不了「内容到底改没改」——需要 v0.5 加钩子。

### ④ 只有三档，把"没查成"混进"证据不足" → 已修

新增第四档 **`unverified`**：模型漏答 / 内部调用失败 / 证据被截断，都属于**核验没做成**，不是"查了没证据"。

| 判定 | 含义 |
|---|---|
| supported | 查了，支持 |
| contradicted | 查了，反驳 |
| insufficient | 查了，证据里没提 |
| **unverified** | **没查成** |

### 当前状态（v0.4.0-experimental.1）

- 结构层三道关卡：**顺序 → 状态 → 日志**
- `promise` 单测 **22/22**，10 个测试文件全绿
- `X_claim` **38.5%**（比 v3 的 39.6% 略降，是顺序校验收紧的合理结果）

## 九、三票制（v0.5）：不再让单一启发式定罪

### 为什么

v0.3 的结构层在真实对话里照样误报，抽出来的错句集中在两类：

1. **元讨论**——我在解释核验机制本身，句子里的「写入/测试/重启」是**被讨论的对象**，不是我的声明
2. **无关失败**——本轮有命令失败，但那失败跟这句话没关系

这正是语言学里的 **use vs mention** 问题（[NAACL 2010](https://dl.acm.org/doi/abs/10.5555/1858146.1858152)）。用词表堵不住，因为我们讨论的就是这些词。

### 别人的做法

[dos-kernel 的 overclaim 基准](https://github.com/anthony-chaudhary/dos-kernel/blob/master/benchmark/agentprocessbench/overclaim.py) 写**三个独立检测器**交叉验证：

| 检测器 | 方法 |
|---|---|
| lexical-assertive | 纯字符串扫描「断言式过去时 + 写动作」 |
| write-verb-grounded | 更严，**排除读操作声明和用户祈使句** |
| effect-witness-grounded | claim vs 两个见证方（环境指标 + 人工标签） |

三者收敛到同一批 34 条（34/250 = 13.6%），用「≥2 同意」防止单启发式漂移。

### 我们的三票制

```
规则票（promise.js + state.js 强否定）
     +
模型票（sentence-audit 句子级三分类）
     ↓
≥2 票一致 → contradicted（votes: 2）
否则      → uncertain，理由写明模型判了什么
```

**只对 contradicted 表决**：supported / uncertain 不调模型。5 秒成本只在准备定罪时花。

**第二票失败 → 全部降级 uncertain**：模型挂了就是没证据，宁可放过不可冤判。

### 一条必须记住的外部结论

> tau2 的 `tool_metrics` **只见证调用成功，不见证正确性**——「预订可以成功，但订错人只有人工看得到」。（presence-not-correctness）

**推论**：我们的结构层永远只能回答「发生没发生」，回答不了「做对没做对」。
后者只有两种途径：**状态核验（③）** 或 **人工**。这句话要写进对外口径，别越界。

### 当前四道关卡（v0.5.0-experimental.1）

| 关卡 | 依据 | 成本 |
|---|---|---|
| ① 顺序 | 证据必须早于声明 | 0 |
| ② 状态 | 文件不存在直接否 | 0 |
| ③ 日志 | 调用/退出码/输出特征 | 0 |
| ④ 表决 | 规则 + 模型 ≥2 票 | 仅 contradicted 时 5 秒 |

测试：11 个文件全绿（`vote` 10/10、`promise` 22/22）。
