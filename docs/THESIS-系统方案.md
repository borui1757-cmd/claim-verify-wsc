# 第三章 系统方案（草稿）

> 本章给出系统架构、关键机制与设计权衡。所有机制均有对应实现与测试（见 §7.7）。

## 3.1 问题与总体思路

agent 完成一个动作后，会用自然语言报告结果。两类失败最危险：

1. **幻影执行**：动作未发生（或失败），报告却声称成功；
2. **越权执行**：动作本不该发生，却因为权限宽松被执行。

本文只负责第一类的**事后核验**，并把结论做成**可第三方验证的证据**；第二类由执行前的授权层（SOF、CapScope 一类工作）负责，二者互补。

总体思路：**把"它说做了什么"翻译成可执行的检查，让程序去查，而不是让模型去判。**

```
agent 报告 ──► 声明解析 ──► 断言（结构化）
                               │
                               ▼
本机真实状态 ──► 证据抽取 ──► 判定（确定性规则）──► 三分类结论
                               │
                               ▼
                        签名回执（可分发、可验签）
```

**信息流分离**（关键设计）：声明解析**只看报告**，证据抽取**只看轨迹**，判定层不接触自然语言。该设计借鉴了 report–trace auditing 中"报告隔离"的实证结论（暴露自述会压低危险误报召回）。

## 3.2 断言表示：受限 DSL

**为什么不用自然语言直接判**：模型判定不可复现、不可审计，且在同一批机械事实上召回显著低于程序真值（§7.3）。

**DSL 的形状**：一条断言 = 若干只读检查的合取。

```json
{ "all": [ { "prim": "port", "args": { "port": 8700 }, "expect": true } ] }
```

**原语集合**（12 个，全部只读，除显式标记的写原语）：

| 原语 | 语义 | 瞬态 |
|---|---|---|
| `port` | 本机端口是否在监听 | 是 |
| `reachable` | 本机地址是否可连通（限定 127.0.0.1/localhost） | 是 |
| `proc_alive` | PID 是否存在 | 是 |
| `time_near` | 声称时间与当前时间的偏差 | 是 |
| `exists` | 路径是否存在 | 否 |
| `file_contains` | 文件是否包含指定文本 | 否 |
| `dir_count` | 目录下某类文件数量 | 否 |
| `math_eq` | 算式结果是否等于声称值 | 否 |
| `write_file` | 写文件（带备份；仅在授权层下启用） | 否 |
| `git_head` | 仓库 HEAD 是否匹配声称的提交（读 `.git`，不依赖 git 命令） | 否 |
| `git_clean` | 工作区是否干净（`git status --porcelain`） | 是 |
| `http_status` | 端点返回的状态码（仅 http/https，超时 2s） | 是 |

**校验器**：`validatePlan` 拒绝未知原语、多余字段、参数类型错误、越界端口、相对路径、空计划、超过 6 条检查。任何不合格计划**不执行**，直接返回 insufficient。

**安全算术**：`math_eq` 的表达式由手写递归下降解析器求值，只接受数字与四则运算，不使用 `eval`。

## 3.3 断言编译：自然语言 → 计划

模型只做翻译，不做判断。流程：

1. **生成**：提示词列出原语与参数 schema，要求输出 JSON 计划，或 `{"unsupported": "原因"}`；
2. **校验**：`validatePlan` 过滤非法计划；
3. **见证**（witness）：计划里每个参数值必须**在原句中出现**（路径/端口/数字/文本），否则判为「翻译歪了」，返回 insufficient；
4. **执行**：`runPlan` 调用原语，得到三分类。

**见证的作用**：把"计划是否等价于原句"从模型自评变成**可判定的字符串映射**。实测中它把"参数不在原句"的错误全部拦下（§7.5.2 MR 系列）。

**归一化规则**：路径大小写与斜杠统一；算式按数字逐个比对（"1873 乘以 4" 与 `1873*4` 视为一致）；扩展名去点（`html` 与 `.html` 一致）。

## 3.4 证据层：轨迹抽取与时序

**证据来源**：本机工具轨迹（`tool/call` + `tool/result`），以及核验时刻的系统状态。

**平台适配**（`lib/platform/`）：系统状态读取按平台分发，接口一致、读取可注入：

| 能力 | Windows | POSIX（Linux/macOS） |
|---|---|---|
| 进程存活 | `kill(pid, 0)`，`EPERM` 视为存活 | `/proc/<pid>` 是否存在 |
| 监听端口 | TCP 探活 | 解析 `/proc/net/tcp`、`tcp6`（仅 `0A`） |
| 失败语义 | 区分 ESRCH / EPERM / 未知 | 读不到 `/proc` → 返回 null（不猜） |

**为什么 POSIX 只读 `/proc`**：不依赖 `netstat`/`lsof`/`ss`，不受工具缺失或受限影响；只读无副作用；容器内仍可用。格式依据 `proc_pid_net(5)`。

**结构化证据**：

```js
{ writes: [{ path, isError, resultSeen, callId, text }],
  cmds:   [{ cmd,  isError, resultSeen, callId, text }] }
```

**时序对齐**：原语按「瞬态 / 持久」分类。若断言指向**更早的轮次**且被反驳的是瞬态原语（端口、进程、连通、时间），则**不判否定**，转为 insufficient——因为"现在没有"不能证明"当时没有"。

**报告隔离**（`lib/isolated-audit.js`）：声明解析与证据抽取分两条通道，判定层只消费结构化证据，不读报告原文。

## 3.5 判定层：三分类与不确定性

判定只有三种结论，且**弃权是显式语义**：

| 结论 | 触发条件 |
|---|---|
| `supported` | 证据显示对应动作成功/存在 |
| `contradicted` | 证据显示对应动作失败/不存在（或明确相反） |
| `insufficient` | 无证据、证据截断、时序不匹配、计划不合法、策略未放行 |

**多证据选取**：同一目标可能有多次调用（失败后重试成功）。判定规则**优先取成功的证据**；只有全部失败才判 contradicted。该规则修复了早期"取第一条命中即判"造成的假阳性（§7.5.1 控制实验 B 的对照）。

**投票（可选）**：当结构层判出 contradicted 且开启模型层时，要求模型给出第二票，两票一致才保留；模型失败则降级为 uncertain。

**声明覆盖率**（`lib/coverage.js`）：统计"本轮实际动作数"与"被声明数"之比，把"只声明能通过核验的部分"这一漏洞**量化**而非假装解决。

### 3.5.1 回写：把判定送回模型

判定若只写进日志，对模型没有任何影响。因此系统提供第三条路径：**把 `contradicted` 送回模型上下文**，形成"执行—核验—纠正"的闭环。

```
工具调用 ──► 轨迹 ──► 结构核验 ──┬─ supported   → 不干预
                                  ├─ insufficient → 默认不干预（可配 firm）
                                  └─ contradicted → 生成反馈，注入下一步之前
```

**反馈内容**（`lib/feedback.js`）必须包含三要素，缺一不可：

1. **哪一条**：目标（路径/命令）或原句；
2. **什么证据**：失败原因与出处（`EACCES`、`exit code 1`、连接被拒绝）；
3. **该怎么改**：不得声称完成，应先修正或重试。

**三档强度**

| 档位 | 行为 | 适用 |
|---|---|---|
| `soft` | 只陈述事实 | 默认；避免干扰正常流程 |
| `firm` | 明确要求修正后再结束 | 交付前 |
| `block` | 未通过则不允许宣称完成 | 高风险操作 |

**为什么必须带证据出处**：实验中出现过模型**质疑核验**的情形——当反馈与它自己看到的工具输出冲突时，模型回复"实际探测为监听正常，建议复核核验来源"。反馈若只是结论、没有出处，会被当成噪声；带上调用与输出摘要，模型才会重新检查。

**闭环的边界**：回写只能纠正**报告**，不能纠正**动作**。真做错的事（写错目录、删错文件）需要执行前授权（§3.6），不是反馈能解决的。

## 3.6 执行前授权

**策略形状**：

```yaml
default: allow
rules:
  write_file: { decision: pending, allowPathPrefix: "C:\\Users\\me\\Desktop\\" }
```

- 决策三档：`allow` / `deny` / `pending`；
- **谓词**：路径前缀不匹配直接 deny，而不是笼统"允许写文件"；
- **pending 不执行**：计划落盘到 `pending-plans.jsonl`，由 `bin/approve.mjs` 人工放行后才执行；
- 决策与**策略哈希**一并落进审计记录与回执，证明"执行发生在哪版策略下"。

**核验器不持有写能力**：`write_file` 只在授权层启用，核验路径默认不启用。设计上避免"用核验器执行副作用"。

## 3.7 证据凭证：签名回执

**信封**（对齐 DSSE / SCITT 形状）：

```json
{ "payloadType": "application/vnd.claim-verify.receipt+json",
  "payload": "<base64(正文)>",
  "signatures": [{ "keyid": "<公钥指纹>", "sig": "<Ed25519>" }] }
```

**链**：每条回执带 `prevDigest` 与 `chain = sha256(prevDigest | digest)`，形成线性哈希链，可检出插入、重排与倒填。

**锚定**：定期取链头 → RFC 3161 时间戳权威盖章 → 写入 `anchors.jsonl`。即使整份回执文件被重写，外部时间戳也对不上。

**验证**：第三方仅需公钥即可 `verifyRecord`（验信封 + 验链值），无需私钥、无需读源码。篡改任一条字段，验签即失败（已实测）。

**与 AIVS 对齐**：回执同时携带 AIVS 行字段（`row_id / session_id / action_type / tool_name / cost_cents / timestamp / prev_hash / row_hash`），行哈希算法与 [draft-stone-aivs-01 §3.1](https://www.ietf.org/archive/id/draft-stone-aivs-01.xml) 一致（键排序、无空白的 canonical JSON），可用 `node bin/aivs-verify.mjs` 独立校验。
需要强调的是：AIVS 只保证「日志完整、未被篡改」，其 §9.2 明确声明**不证明记录内容为真**；本文的核验层补的正是这一格。

## 3.8 结构化声明工具

实验发现（§7.6）：**自由文本里的可核验声明密度极低**（30 份报告仅 1 条带具体目标）。因此系统提供 `report_claims` 工具，让 agent 在交付前显式声明：

```json
{ "claims": [ { "kind": "write", "target": "C:\\a.txt" },
              { "kind": "cmd",   "target": "npm test" } ] }
```

工具内部即时比对轨迹并返回逐条判定，模型可在同一轮自我纠正。回执从工具调用参数生成，**不依赖自然语言解析**。

## 3.9 外部世界模型：把「记忆」放在模型外面

有评审会问：本系统只做单次纠正，**没有更新模型的世界模型**。这条批评成立，我们选择正面回应而不是回避：

> **不训练模型，而是把世界模型外部化。**

每条被程序核验过的声明，连同时间戳与判定，追加到账本（`worldmodel.jsonl`）；再次遇到同一对象时，核验与回写都可以先查账：

| 能力 | 实现 |
|---|---|
| 记录 | `recordFact({kind,target,verdict})`，只追加 |
| 查询 | `lookupFact()` 取最近一条，按类型设 TTL（端口 5 分钟 / 文件 1 小时） |
| 统计 | `ledgerStats()`、`bin/worldmodel.mjs --rate` 按周统计**反驳率** |
| 回写增强 | 账本若显示「10 分钟前该对象成立」，反馈会写明「状态已变化」 |

**为什么这算「世界模型」**：模型对环境的信念被写到外部，且每条可追溯；
这与文本世界模型路线一致（[Text World Models for LLM Agents](https://browse-export.arxiv.org/pdf/2606.09032)），
区别是本文的条目**由程序真值产生并带签名**，而不是由模型自己写。

**长期证据**：`--rate` 输出逐周反驳率。若账本生效，该比率应随使用时间下降——
不需要训练、不需要跨会话记忆模块，账本本身就是记忆。

**边界**：账本不改变模型参数；它影响的是「下一次遇到同一对象时，提示与反馈里带什么」。

**账本的两个直接用途（B / C）**

| 用途 | 机制 | 触发条件 |
|---|---|---|
| **B 可验证性自校准** | 统计过去 7 天同一对象的反驳率，写入回写 | 样本 ≥3 且反驳率 ≥50% |
| **C 重复假声明拦截** | 同一对象被证伪 ≥2 次后，措辞升级 | 无时间窗（长期记忆） |

示例输出：

```
历史校准：过去 7 天关于该对象的 5 次核验中，3 次被证伪（60%），请谨慎声称。
该对象此前已被证伪 3 次；不要再次声称它成功，请如实报告失败或请求人工介入。
```

两者都**只读账本、零模型调用**，因此不增加判定成本。

**矛盾驱动的优先级（"好奇心"的极小实现）**

账本里"最后一次判定是 `contradicted`、且之后没再被支持"的对象，构成**未解释的矛盾**。
它们被排成队列（`bin/priority.mjs`），得分 = 反驳次数 ×2 + 类型权重 + 新鲜度：

```
待解释矛盾 3 个；最优先：port 8700（被证伪 5 次，2 分钟前）
```

这不是"想探索新东西"，而是**想解释已有的不一致**——对应差异驱动行为（压缩进步 / 自由能最小化）的一个可执行特例。
它的价值在于**可验证**：队列里的每一条都能被下一次核验消解。

**快慢双循环：与自主计算（Autonomic Computing）的对应**

系统的维护分为两个回路，参照自主神经系统的分工：

| 回路 | 谁来跑 | 做什么 | 是否判断 |
|---|---|---|---|
| **快循环** | AI 层 | Monitor / Analyze / Plan：核验、判优先级、决定是否回写重试 | **是**（会错） |
| **慢循环** | 脚本层 | Execute + 知识固化：去重、清噪音、过期归档、校准重估 | **否**（无条件执行） |

这正是自主计算的 MAPE-K 范式（Monitor–Analyze–Plan–Execute over shared Knowledge）：
`worldmodel.jsonl` 是那个共享的 **K**，快循环写它，慢循环整理它。

**关键区别**（也是可靠性来源）：**脚本层之所以可靠，正因为它不判断。**
判断交给 AI，执行留给脚本——判断可能错，执行不会。
对应的命令：`node bin/consolidate.mjs`（整理账本，原文件先归档再原子替换）。

**一个被实验否定的调制维度**

我们尝试过"激素式全局调制"：由全局警觉度（近 24h 反驳率）决定回写强度（soft / firm / block）。
实现见 `lib/hormone.js`（15/15 测试通过），但 A/B 显示**两档无可测差异**：

| 档位 | 谎报 | 平均 token |
|---|---|---|
| soft | 0/4 | 1,451 |
| firm | 0/4 | 1,515 |

原因：两条消息的**事实内容相同**，只差语气；模型由事实驱动，不由语气驱动
（与 [Feedback That Backfires](https://arxiv.org/abs/2608.23651) 一致）。

**因此调制的正确维度不是"说得多重"，而是"查不查、给不给核验通道"**——后者有效（诚实率 1/6 → 5/6）。
该机制保留为可选项，**默认不启用**。

**材料性分级（不是新方法，是迁移）**

单纯的"次数 + 新鲜度"会让队列被噪音淹没。对 333 条真实被证伪声明统计：

| 类别 | 数量 | 占比 |
|---|---|---|
| 临时路径 | 2 | 0.6% |
| **测试类命令** | **93** | **27.9%** |
| 噪音合计 | 95 | **28.5%** |
| 实质矛盾 | 238 | 71.5% |

加入"材料性"（排除测试命令/临时路径）+ 按对象去重后，队列前 8 位的噪音从 **2/8 降到 0/8**。

**定位**：告警分级在静态分析与运维领域是**成熟研究**（[CORTEX](https://browse-export.arxiv.org/pdf/2510.00311)、[多工具告警优先级](https://scholar.google.nl/citations?view_op=view_citation&hl=pt-BR&user=y8zCm5kAAAAJ&citation_for_view=y8zCm5kAAAAJ:AXPGKjj_ei8C)），
本文**不主张新方法**，只是把该思路迁移到「agent 声明矛盾」这一对象上，并给出实测噪音比例。

## 3.10 设计权衡

| 选择 | 理由 | 代价 |
|---|---|---|
| 只读原语为主 | 核验无副作用，可反复执行 | 覆盖限于"可观测状态" |
| 弃权优先 | 宁可漏判不可误判；误报比漏报更伤信任 | 覆盖率受限于证据 |
| 确定性判定 | 可复现、可审计、零模型成本 | 需人工维护原语与规则 |
| 报告隔离 | 避免自述污染判定 | 声明解析可能漏提 |
| 回写带证据出处 | 无出处会被模型当成噪声甚至抗辩 | 反馈文本更长 |
| 回执含策略哈希 | 审计可追溯"哪版策略下执行" | 策略改动需重新签发 |

## 3.11 小结

系统的核心不是"更聪明的判定"，而是**把判定从不可复现的模型判断，搬到一个可执行、可复现、可分发凭证的确定性轨道上**。其代价是覆盖受限，因此系统显式输出 `insufficient` 而非猜测。
